# Go 编码规范

### GO-001：类型、命名与注释

- 包名简短、小写且有明确含义；导出名称避免重复包名，缩写采用一致的 `HTTP`、`URL`、`ID` 写法。
- 局部变量按作用域选择清晰名称；用具体类型表达数据，避免滥用 `any`。
- 接收者类型保持一致，需要修改状态或避免复制锁等值时使用指针接收者。
- 供其他包使用的导出 API 提供 Go 文档注释，以标识符起句；包文档使用 `Package <name>` 形式，弃用标记使用 `Deprecated:`。注释内容遵守 [BASE-011](../AGENTS.md)。

### GO-002：保持包边界清晰

- 按 GO-011 组织业务包，相关代码保持内聚，避免循环依赖。
- HTTP 处理负责解析与响应映射，可独立验证的业务规则放领域层，多步用例使用明确 DTO 及 `context.Context`，不依赖 `gin.Context`；数据访问操作明确接收连接或事务。
- 公共 API 尽量小，接口按使用方实际需要定义，不为每个结构体机械创建接口。

### GO-004：处理错误并保留语义

- 检查并处理返回的错误，业务失败通过返回值表达，不以 `panic` 代替正常错误流程。
- 需要保留错误链时使用 `fmt.Errorf("动作说明: %w", err)`，以 `errors.Is` / `errors.As` 判断错误。
- 不比较错误文案，不泄漏底层敏感信息；避免同一错误在每层重复记录。
- 仅把已确认的凭据无效或会话失效映射为认证失败；数据库超时、连接和扫描故障保留基础设施错误语义。内部错误保留可定位的脱敏原因和操作上下文，不能只记录通用失败文案。

### GO-005：管理上下文和资源生命周期

- 请求内工作传递请求上下文；`context.Context` 通常作为首个参数，不存入业务结构体，不随意切断取消链。
- 创建超时或取消上下文后调用取消函数；goroutine 明确退出条件和错误处理，避免无界并发。
- 及时关闭本层拥有的文件、响应体和行迭代器，检查迭代及提交错误，缩小锁和事务持有范围。

### GO-006：显式处理输入与输出

- 校验绑定后的输入，明确允许写入和对外输出的字段。
- 校验 JSON 顶层形状，按契约区分字段缺省、`null` 和零值，防止无效请求被当作清空或覆盖操作。
- 避免将外部输入直接赋给服务端控制字段，排除非公开敏感信息。
- 限流、鉴权等中间件提前返回时，仍遵守适用的响应、CORS 和安全头契约；预检与业务请求按各自语义处理。

### GO-007：安全访问数据

- 查询使用参数绑定，不可绑定的动态标识符使用受控白名单。
- 事务明确提交与回滚责任，错误路径释放资源，避免持有事务执行无关长耗时操作。
- 在开启写事务或取得业务锁前完成有界请求体读取及不依赖数据库的校验。锁的对象、模式、顺序和持有范围必须对应具体并发不变量，不能默认让所有读取取得同一排他锁。

### GO-008：保持实现可理解

- 用提前返回和准确命名降低嵌套，抽取具有独立语义的函数，避免只为缩短代码制造跳转。
- 共享抽象针对已出现的共性，避免万能工具包与隐式副作用。

### GO-010：格式与生成代码

- 使用 `gofmt` 格式化修改的 Go 文件。
- 修改生成代码时更新其真实来源并重新生成，保持来源和产物一致。

### GO-011：四层内按业务能力组织目录

```text
server/
  cmd/
    api/
      main.go                     # API 程序入口、退出信号与错误退出
  internal/
    bootstrap/                    # 配置、依赖组装与进程资源生命周期
    domain/
      saas/                       # 企业、账号、会话、纯规则及领域存储契约
    app/
      saas/
        usecase/                  # 权限、用例编排、事务与并发不变量
        dto/                      # 用例输入与结果、对外字段契约
        port/                     # 用例所需事务与微信等外部能力契约
      storage/                    # 应用公共对象存储契约
    infra/
      persistence/
        saas/                     # 领域存储实现、私有 ORM 模型与映射
      database/                   # 数据库连接与驱动配置
      wechat/                     # 微信协议客户端与应用端口适配
      storage/                    # 对象存储配置与 filesystem、S3 实现
    transport/
      http/                       # Gin 路由、绑定、中间件与响应
  tests/
    integration/                  # 真实数据库与跨操作流程
```

- 采用 `domain / app / infra / transport` 四层，各层内部按实际业务能力分包；紧密共享事务与业务不变量的能力保持内聚，不按每条路由拆包。新增业务在对应层按需要落位，不预建空的 entity、aggregate、event、Redis 或其他目录。
- 依赖方向为 `transport → app → domain`；`infra` 实现 `domain` 和 `app` 定义的消费方契约，不反向依赖用例实现或传输层。`domain` 不依赖其他层，领域契约不依赖 Gin、ORM、数据库驱动或具体技术实现。
- HTTP 专属绑定与响应属于 `transport`，用例输入和结果属于 `app/<业务>/dto`；领域对象不携带 JSON、ORM 等技术标签。持久化模型及其映射留在 `infra/persistence`，不直接作为接口结果。领域仓储表达领域数据操作，用例需要的事务协调、锁和外部能力契约按其所有权定义，不能为目录形式机械下沉所有接口。
- `bootstrap` 统一创建依赖、组装用例和 HTTP 入口，并管理进程拥有的连接与后台任务；`cmd/api/main.go` 只处理命令入口和退出信号。HTTP 层接收消费方定义的用例接口，不能接收数据库并在内部创建业务服务；业务用例接收所需端口，不能创建 Repository、微信客户端或对象存储实现。四层不反向依赖 `bootstrap`，配置和连接不通过可变全局变量隐式读取。
- 同一业务能力内按用例明确职责，共享身份及事务规则不等于共用一个万能公开 Service。跨企业、账号和会话的原子操作由应用用例协调同一事务，不能通过服务相互调用各开事务。数据库列名与 ORM 更新字典留在 `repository`，业务通过类型化变更表达字段缺省和零值。
- 通用技术实现放 `infra`，平台管理员和企业管理属于 SaaS 业务。跨业务调用公开用例或消费方定义的小接口，不直接读写另一业务的持久化实现。对象存储通过应用公共契约接入，业务负责对象 key 与归属，具体实现不耦合头像或 MinIO 产品。
- 可执行程序使用 `cmd/<程序>/main.go`，API 启动命令为 `go run ./cmd/api`，移动入口时同步文档与实际调用方。局部测试用 `*_test.go` 随包放置，fixture 放消费包的 `testdata/`。
- 包名简短小写，Go 文件使用小写加下划线命名。目录创建与存量迁移遵守 [DIR-001 / DIR-005](../agent-rules/directories.md)。
