# Go 编码规范

### GO-001：类型、命名与注释

- 包名简短、小写且有明确含义；导出名称避免重复包名，缩写采用一致的 `HTTP`、`URL`、`ID` 写法。
- 局部变量按作用域选择清晰名称；用具体类型表达数据，避免滥用 `any`。
- 接收者类型保持一致，需要修改状态或避免复制锁等值时使用指针接收者。
- 导出注释与标识符对应；注释解释约束、原因和不直观的取舍，随代码同步更新。

### GO-002：保持包边界清晰

- 沿用已有包结构，相关代码保持内聚，避免循环依赖。
- 公共 API 尽量小，接口按使用方实际需要定义，不为每个结构体机械创建接口。

### GO-004：处理错误并保留语义

- 检查并处理返回的错误，业务失败通过返回值表达，不以 `panic` 代替正常错误流程。
- 需要保留错误链时使用 `fmt.Errorf("动作说明: %w", err)`，以 `errors.Is` / `errors.As` 判断错误。
- 不比较错误文案，不泄漏底层敏感信息；避免同一错误在每层重复记录。

### GO-005：管理上下文和资源生命周期

- 请求内工作传递请求上下文；`context.Context` 通常作为首个参数，不存入业务结构体，不随意切断取消链。
- 创建超时或取消上下文后调用取消函数；goroutine 明确退出条件和错误处理，避免无界并发。
- 及时关闭本层拥有的文件、响应体和行迭代器，检查迭代及提交错误，缩小锁和事务持有范围。

### GO-006：显式处理输入与输出

- 校验绑定后的输入，明确允许写入和对外输出的字段。
- 避免将外部输入直接赋给服务端控制字段，排除非公开敏感信息。

### GO-007：安全访问数据

- 查询使用参数绑定，不可绑定的动态标识符使用受控白名单。
- 事务明确提交与回滚责任，错误路径释放资源，避免持有事务执行无关长耗时操作。

### GO-008：保持实现可理解

- 用提前返回和准确命名降低嵌套，抽取具有独立语义的函数，避免只为缩短代码制造跳转。
- 共享抽象针对已出现的共性，避免万能工具包与隐式副作用。

### GO-010：格式与生成代码

- 使用 `gofmt` 格式化修改的 Go 文件。
- 修改生成代码时更新其真实来源并重新生成，保持来源和产物一致。
