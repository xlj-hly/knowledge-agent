# Vue 与 uni-app 编码规范

### UNI-001：沿用页面与组件风格

- 修改已有页面时沿用其语言和 API 风格；新增代码遵循已有一致约定。
- 组件通过 props 和事件协作，不直接修改 props；`data()` 返回独立状态，列表使用稳定唯一的 key。

### UNI-002：保持代码职责清晰

- 按 UNI-007 组织目录，将复杂计算、请求处理与展示逻辑适度分离。
- 有实际复用时再提取公共能力，避免万能工具模块和循环依赖。

### UNI-003：正确使用平台能力

- 优先使用 uni-app 组件与 API，平台差异通过条件编译或能力检测处理。
- H5 专用代码限制在对应分支，公共代码不假设存在 DOM、`window` 或浏览器存储。
- 核对平台 API 的支持范围，处理失败和不支持的情况。
- 存储的读、写、删都处理失败；平台回调中的异常必须使对应异步操作确定结束。会话失效时先使内存状态与授权视图失效，存储清理失败不能中断通知与请求结束。

### UNI-004：管理响应式状态与生命周期

- 派生值优先使用计算属性，侦听器用于必要副作用，避免循环回写和重复请求。
- 区分应用、页面与组件生命周期，避免重复注册监听与初始化，按资源生命周期清理。
- 异步操作处理失败、取消和响应乱序，忽略失效结果，避免覆盖较新状态。
- 按 [ARCH-003](../agent-rules/architecture.md) 处理身份或租户变化；页面恢复时核对实际身份，身份或租户变化后重建对应表单与授权视图，不沿用上一身份的草稿。

### UNI-005：明确数据边界

- 调用遵循现有接口，修改数据结构时检查使用方，对外部输入和读取结果执行必要校验。
- 服务端秘密不得进入客户端包或公开配置，日志排除敏感信息。

### UNI-006：限定页面与样式影响

- 新增页面同步维护 `pages.json`，修改共享组件、全局样式或入口时检查影响范围。
- 布局和尺寸沿用项目约定，平台专属样式限制在对应范围。

### UNI-007：页面优先，保留平台路由与生命周期

```text
uniapp/
  src/
    main.js                       # 应用创建与挂载
    App.vue                       # 应用生命周期与全局样式
    pages.json                    # 页面与分包注册
    manifest.json                 # 平台构建配置
    pages/
      <route>/
        <route>.vue               # 完整页面及平台生命周期入口
        components/               # 按需拆分的页面专属组件
        validation.mjs            # 页面专属校验，按需建立
        state.mjs                 # 页面专属状态与操作，按需建立
    api/
      request.mjs                 # uni.request / uni.uploadFile、错误、认证与请求域名策略
      account.mjs                 # 账号接口及相应契约
    stores/                       # 按需建立的跨页面客户端状态
    components/
      <name>/<name>.vue           # easycom 通用组件，小写 kebab-case
    composables/                  # 按需建立的跨页面组合式逻辑
    utils/                        # 按用途拆分的纯函数与平台适配
    static/                       # 按静态路径引用的公开资源
  tests/
    integration/                  # 跨模块集成测试
    e2e/                          # 目标平台流程与启动辅助
```

- 页面实现统一放实际注册的 `pages` 或分包目录，`onLoad/onShow/onUnload` 等平台适配留在页面。页面专属组件、状态、校验、样式和测试跟随页面，按职责拆分，不把所有功能集中到首页或 `App.vue`。
- 页面调用 `api`、跨页面 Store 与公共组件；API、Store、公共组件及工具不反向引用具体页面，页面之间不读取对方的私有实现，遵守 [DIR-002](../agent-rules/directories.md)。
- 请求与响应契约按业务集中在 `api`，通用传输、认证与请求域名策略集中配置；租户由后端按请求 Host 识别，客户端不通过自定义头覆盖。页面表单草稿留在页面，跨页面状态按职责放 `stores`，明确身份切换和清理责任。
- `components` 放跨页面组件并遵循 easycom 约定；页面专属组件留在页面旁显式导入，不因自动注册而上提。公共组件可以包含应用展示语义，基础 UI 不隐式切换身份或执行权限判断。
- 跨页面复用且具有独立维护边界的能力可以再提取业务模块，不默认建立 `features` 层；使用 `composables` 不要求存量 Options API 改为 Composition API。
- 新增或移动页面同步 `pages.json`、分包与资源路径；需要分包时，按平台要求在对应包内组织页面和业务，检查依赖及包体归属。`static` 只放公开资源，不放业务代码或测试数据。
- 页面专属 Vue 组件用 PascalCase，页面路径与通用 easycom 目录用小写 kebab-case；普通模块按用途命名，沿用所属模块的 JavaScript / TypeScript 选择。逻辑和组件测试靠近实现，跨模块与平台流程放 `tests/`。
- 目录树中的 `.mjs` 示例不要求语言迁移；目录创建与迁移遵守 [DIR-001 / DIR-005](../agent-rules/directories.md)。

### UNI-008：注释表达组件契约与平台限制

- 对调用方需理解的 props、事件及公共操作约束按需编写文档注释；模板注释只说明难以从结构理解的条件、插槽或交互约束。
- 平台分支说明不直观的限制或兼容原因，保留 `#ifdef` / `#endif` 等条件编译指令；其余说明遵守 [BASE-011](../AGENTS.md)。
