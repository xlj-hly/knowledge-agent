# React 与 TypeScript 编码规范

### WEB-001：保持组件职责清晰

- 应用入口组装路由与应用依赖；页面及其专属表单、弹窗和交互归对应页面目录，跨页面展示组件归 `components`，API 适配层不反向依赖页面。
- 按 WEB-007 组织目录，按独立职责拆分组件、Hook 和业务操作，使状态与变化范围可单独理解和验证。
- 有实际复用时再提取公共能力，避免过度抽象和循环依赖。

### WEB-002：遵循组件与 Hook 规则

- 渲染保持纯粹，不修改 props、state 或外部共享值，派生值优先直接计算。
- 普通 Hook 只在组件或自定义 Hook 顶层调用；React `use` 的特殊调用方式遵循其 API 约束。
- Effect 用于同步外部系统，声明实际依赖，清理监听、订阅与计时器。

### WEB-003：保持类型安全

- 为组件输入、事件和业务数据定义清晰类型；外部未知值使用 `unknown`，缩小类型后使用。
- 不用 `any`、非空断言或强制转换掩盖缺失校验，必要断言应具有可信前提并限制范围。
- 遵循项目编译选项，纯类型导入使用 `import type`。

### WEB-004：明确数据边界

- 调用遵循现有接口，修改数据结构时同步检查使用方。
- 传输处理与渲染逻辑分开，对外部数据执行必要校验并处理异常值。
- 服务端秘密不得进入客户端包或公开配置，日志排除敏感信息。

### WEB-005：处理异步错误与过期结果

- 异步操作明确处理失败，避免吞掉异常。
- 取消已失效请求或忽略过期结果，避免旧响应覆盖新状态、卸载后继续更新状态。
- 关键请求设置合理等待期限，或提供可终止等待与恢复的路径，区分主动取消、超时和网络失败，避免界面无限停留在忙碌状态。
- 写入期间明确离开页面的处理方式；响应丢失或客户端取消后结果不确定时，重新确认服务端状态并刷新相关数据，不能把取消视为回滚。

### WEB-006：限定样式影响

- 样式靠近所属组件，使用项目已有命名与尺寸约定。
- 修改全局选择器或共享样式时检查影响范围，避免无关页面受到污染。

### WEB-007：页面优先，公共能力按职责集中

```text
react-app/
  src/
    main.tsx                      # 浏览器挂载入口
    App.tsx                       # 应用根组件与组装
    router/                       # 路由注册、访问保护与导航规则
    layouts/                      # 平台端、企业端等布局与导航展示
    pages/                        # 页面及其专属组件、逻辑、样式与测试
    api/
      request.ts                  # 请求、超时、错误、认证与同源请求策略
      auth.ts                     # 认证接口及相应契约
      account.ts                  # 个人账号接口及相应契约
      members.ts                  # 成员管理接口及相应契约
      tenants.ts                  # 企业接口及相应契约
    stores/                       # 按职责拆分的跨页面客户端状态
    components/                   # 跨页面组件，可区分 ui 与应用展示组件
    hooks/                        # 跨页面复用的 Hook
    utils/                        # 按 date、storage 等用途命名的纯函数
    assets/                       # 通过 import 使用的公共资源
  public/                         # 必须按原路径公开的静态资源
  tests/
    integration/                  # 跨模块集成测试
  e2e/                            # 浏览器流程、服务启动与清理
```

- 路由对应的完整页面实现统一放 `pages`，页面目录名称与分组按实际路由和业务需要确定；角色和租户隔离通过会话与授权实现。路由注册放 `router`，布局放 `layouts`，不另外创建只转发页面的同名业务层。
- 页面专属表单、弹窗、Hook、校验、样式和测试跟随页面；需要拆分时使用页面内的 `components/`、`hooks/` 等子目录。跨页面使用时再提取公共能力，页面之间不直接读取对方的私有实现。
- API 按业务拆文件或子目录，传输、认证和请求域名策略在请求层集中配置；租户由后端按请求 Host 识别，客户端不通过自定义头覆盖。接口类型与响应解码靠近对应 API，避免一个万能 API 文件。请求层、Store、公共组件和工具不依赖具体页面或路由注册模块。
- Store 可以调用 API；请求层需要令牌或失效通知时，通过参数、回调等明确契约接入，不反向导入调用自己的 Store。
- 应用入口和路由组合页面、布局与访问保护，页面调用 API、Store 和公共组件；布局通过导航数据或回调协作，路由路径常量按需独立，避免路由与页面互相导入。依赖边界遵守 [DIR-002](../agent-rules/directories.md)。
- 公共组件可以表达本应用的品牌、身份摘要等展示语义；基础 UI 不隐式承担权限判断或租户切换。跨页面状态放 `stores` 并按会话等职责拆分，不集中建立承载所有业务状态的全局 Store。
- 需要跨组件共享的客户端状态使用 Zustand；表单草稿、弹窗和其他局部状态优先留在组件或业务 Hook。Store 不持有组件实例或路由组件，不把服务端权限判断转为仅信任客户端状态。
- 持久化使用 Zustand `persist`，显式选择存储介质、键与恢复范围，用 `partialize` 白名单保存必要字段。会话按身份空间与企业隔离，只恢复令牌并向服务端验证身份；密码、表单草稿、请求状态和操作函数不持久化。恢复数据按外部输入校验，不能覆盖运行时动作；存储失败仍须完成内存状态失效并反馈原因，遵守 ARCH-003 / WEB-005。
- 多个页面共同使用且具有独立规则、状态和维护边界的能力，可以按实际需要提取业务模块；不默认建立 `features` 层，也不为了套目录给每个页面增加第二套入口。
- 页面样式与资源靠近消费组件，布局样式放 `layouts`，全局基础样式留在入口样式文件。组件用 PascalCase，Hook 用 `useXxx`，页面目录用小写 kebab-case；普通模块按 `validation`、`session` 等具体用途命名。
- 单元与组件测试用 `*.test.ts` / `*.test.tsx` 靠近实现，已有有效 `.test.mjs` 可以保留；跨模块测试与 E2E 分开。目录创建与迁移遵守 [DIR-001 / DIR-005](../agent-rules/directories.md)。

### WEB-008：使用标准文档注释表达公开契约

- 组件、Hook 和公共操作存在调用方需理解的约束时，使用 JSDoc 说明参数语义、状态所有权、副作用或清理责任；不重复 TypeScript 已表达的参数和返回类型。
- `@deprecated` 等工具标签保留标准写法；其余说明遵守 [BASE-011](../AGENTS.md)。
