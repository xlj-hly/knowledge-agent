# Proposal

## Why

SaaS 基座已完成，需要在 React 端贯通配置、资料管理、处理、检索与聊天问答。以 AnythingLLM 的产品交互和配置体验为主要参考，使用适合本项目的 WeKnora Go 底层能力。

## What Changes

- 增加文档知识库、资料与分块管理，后台处理、失败重试及检索测试。
- 页面配置 Chat / Embedding 模型、服务商预设与模型发现、向量存储连接、企业默认配置、System Prompt 和文本分割；保留原件至现有统一对象存储。已有授权配置接口返回实际模型 API Key、完整向量 config 和平台微信 AppSecret，表单原值回填并完整保存，不保留隐式凭据继承或按模型 ID 回读密钥的测试路径。
- 采用符合 Go 四层依赖的类型化服务商定义和显式注册，把目录、Logo、能力校验与协议适配关联起来；补充已有兼容协议的服务商，页面统一消费目录，不维护第二份品牌名单。
- Prompt 与切分方案使用独立产品预设目录，和模型服务商目录分开注入；页面从同一目录读取切分策略名称与选项，避免配置内容散落在业务和页面中。
- 支持无需模型的关键词检索，以及使用真实 Embedding 与所选向量引擎的向量和混合检索；参考 AnythingLLM 与 WeKnora 页面选项接入 13 个远程向量引擎模块。
- 增加用户所属的会话、消息、流式回答和来源引用，以聊天为企业首页；知识库独立管理资料，支持明确的索引重建。
- LLM 模型列表提供企业唯一启用操作，`ai_settings.chat_model_id` 是唯一状态；所有新旧会话下一条消息读取当前启用模型，流式请求固定开始时配置。会话模型仅保留服务端最近生成快照，聊天页不选择模型，保存其他默认设置不覆盖启用状态。
- 聊天沿用标准侧边文字导航、顶部栏和页面内容区，在内容卡片内提供历史、空态中心输入和消息后底部输入；用户消息靠右、AI 回答靠左，历史与流式回答统一安全渲染 Markdown，支持输入法保护、复制、来源抽屉及上滚阅读时停止自动跟随。
- 复用现有企业身份、逻辑关联和四层结构，不引入公有私有、FAQ、Wiki、Agent 框架或新的 Workspace 层。
- uniapp 本轮不变；更新完整建表 SQL、说明和实际本地应用数据库，保持服务可访问。

## Capabilities

### New Capabilities

- `document-knowledge`: 知识库、资料、分块的生命周期及检索。
- `knowledge-connections`: 页面维护向量存储连接及引用、清理一致性。
- `ai-configuration`: Chat / Embedding 模型、服务商与模型预设、发现和测试、企业唯一启用 LLM 与新建模板。
- `chat`: 用户会话、动态使用企业启用 LLM、普通聊天与知识问答、流式生成、停止、历史及来源快照，以及简洁的 Markdown 聊天交互。

### Modified Capabilities

无。

## Impact

涉及 server 四层业务和应用组装、React 页面/API/路由、db/saas.sql、部署上传容量及文档。复用 WeKnora 切分源码保留 MIT 声明。已有 SaaS 账号和数据保留，外部服务不可用时报告真实故障，不返回模拟检索结果。
