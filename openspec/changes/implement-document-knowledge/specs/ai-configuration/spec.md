# Spec Delta

## Purpose

统一管理企业 Chat 与 Embedding 模型，提供服务商与参数预设、发现和测试；企业唯一启用 LLM 用于所有会话下一条消息，其余模板用于新建知识库和会话。

## ADDED Requirements

### Requirement: 简洁配置入口与分组编辑

系统 SHALL 使用侧栏作为跨页配置导航，模型页面不重复提供跳转相同菜单的 Tab。模型服务商 MUST 提供品牌识别与直接配置入口，目录只展示实际支持能力；企业默认配置先显示当前值摘要，用户一次编辑并保存一组参数，取消不写入，失败保留草稿。

#### Scenario: 直接配置服务商
- **WHEN** 用户点击带 Logo 的服务商卡片
- **THEN** 直接打开该服务商的连接参数，并保留候选模型、发现、手填与真实调用测试能力

#### Scenario: 单独保存提示词
- **WHEN** 用户先在 LLM 列表启用模型，再编辑并保存 System Prompt
- **THEN** 启用状态和提示词均持久化，提示词保存不覆盖当前启用模型；取消提示词编辑不改变当前模板

### Requirement: 企业模型配置与用途

系统 SHALL 统一存储 Chat 与 Embedding 模型，按用途校验协议与维度，由企业管理员管理；现有读取权限及企业隔离保持。已授权配置响应 MUST 包含实际 api_key 字符串并回填表单，不使用 has_api_key 标记。保存 SHALL 按当前完整表单替换，不继承旧凭据；空串直接清空，必填凭据为空时拒绝。凭据 MUST 不进入静态包、未授权接口、日志或浏览器持久化。

#### Scenario: 配置两种模型能力
- **WHEN** 管理员分别保存 LLM 和 Embedder
- **THEN** LLM 用于对话，Embedder 用于向量化；跨用途引用被拒绝，已有授权配置读取返回实际 api_key

#### Scenario: 回填与清空凭据
- **WHEN** 有读取权限的本企业用户重新打开模型配置，管理员清空可选 api_key 后保存
- **THEN** 表单先显示已保存原值，保存后 api_key 为空，不恢复旧凭据；必填凭据为空时保存被拒绝

### Requirement: 服务商预设和实际调用测试

系统 SHALL 提供 OpenAI、DeepSeek、通义千问、硅基流动、Ollama 和自定义 OpenAI 兼容服务的已实现能力预设，允许远端模型发现及手填模型。当前表单测试不要求先保存，发现与测试 MUST 使用当前表单中的地址、用途及 api_key，不接受已存模型 ID 回读凭据；Embedding 测试能够检测真实维度。

#### Scenario: 使用预设发现模型
- **WHEN** 管理员选择预设并填写有效凭据后发现和测试模型
- **THEN** 实际访问所选服务并显示真实结果，预设本身不被视为服务可用证明

#### Scenario: 未保存表单检测维度
- **WHEN** 管理员输入 Embedder 的地址和模型名后直接测试
- **THEN** 返回实际输出维度供保存使用，失败明确反馈且不伪造向量

#### Scenario: 测试当前凭据
- **WHEN** 管理员编辑模型表单中的 api_key 后直接发现或测试
- **THEN** 实际调用使用本次表单值，不读取或继承已存模型凭据，记录不因测试被修改

### Requirement: 类型化服务商注册与统一目录

系统 SHALL 通过 Go 类型化定义和显式注册集中维护服务商名称、Logo、默认地址、Chat / Embedding 能力、模型候选、凭据提示和发现支持。页面 MUST 只消费服务端目录，不按品牌维护第二份映射。配置校验、发现、测试、流式聊天与向量化 MUST 使用同一注册目录；领域与业务流程不得维护服务商品牌到协议的分支。注册构建后只读，重复 ID、缺少驱动、未知服务商和不支持用途 MUST 明确拒绝。

#### Scenario: 增加兼容服务商
- **WHEN** 开发者通过模块定义和显式注册增加一个现有协议的服务商
- **THEN** 页面可搜索并展示其 Logo、默认连接和能力，配置与实际协议调用可用，聊天和知识库业务无需增加品牌分支

#### Scenario: 目录独立与失败隔离
- **WHEN** 调用方修改返回的目录或提交未注册服务商及错误用途
- **THEN** 注册实例和其他请求不受影响，无效调用在外部请求前被拒绝

### Requirement: 企业新建模板

系统 SHALL 提供默认 Embedder、向量连接、System Prompt、生成、检索、解析及切分模板和可选预设。新建对象复制相应默认值，保存模板 MUST 不修改已有知识库、会话或消息。企业启用 LLM SHALL 单独管理，不适用仅新建时复制的模板规则。未配置模型和连接时保留为空并在使用相应能力时提示。

#### Scenario: 修改模板后恢复旧对话
- **WHEN** 管理员修改企业 Prompt 或生成参数后用户重新打开既有对话
- **THEN** 旧对话保留自身配置，新对话使用新模板

#### Scenario: 新建知识库使用模板
- **WHEN** 用户新建知识库并未覆盖 Embedder、向量或切分配置
- **THEN** 使用企业模板，默认混合索引缺少连接时明确提示配置而非降级

### Requirement: 企业唯一启用 LLM

系统 SHALL 以 ai_settings.chat_model_id 记录企业唯一启用 LLM，由企业管理员在 LLM 模型列表通过无请求体的 PUT /api/ai/models/:id/activate 操作切换并返回完整 Settings。启用目标 MUST 属于当前企业且用途为 chat。Settings 响应 SHALL 包含 chat_model_id，SaveSettings 输入 MUST 不接受该字段，保存其他模板配置 MUST 保留当前启用状态。

#### Scenario: 启用聊天模型
- **WHEN** 企业管理员在 LLM 列表启用同企业的 chat 模型
- **THEN** 该模型成为唯一启用 LLM，接口返回完整 Settings，新旧会话下一条消息使用它

#### Scenario: 无效启用目标或身份
- **WHEN** 普通成员尝试启用，或目标属于其他企业、用途为 embedding
- **THEN** 操作被拒绝，原启用状态保持不变

#### Scenario: 旧模板表单不能覆盖启用状态
- **WHEN** 管理员切换启用 LLM 后保存先前打开的 Prompt 或其他模板表单
- **THEN** 保存输入不含 chat_model_id，当前启用状态保留，响应返回最新完整 Settings

### Requirement: 独立产品预设目录

系统 SHALL 将 Prompt 模板、切分参数方案和已有切分策略元数据按类别模块化，通过专用只读目录提供并显式注入应用用例。产品预设 MUST 不由模型服务商 Registry 维护。页面 MUST 从返回的 chunk_strategies 读取切分策略名称及选项，不维护第二份策略映射；增加方案不得冒充增加执行算法。无效或重复注册 MUST 在组装时拒绝，目录读写副本不得影响其他调用方。

#### Scenario: 读取独立预设目录
- **WHEN** 用户进入默认配置或知识库配置
- **THEN** 提示词、切分方案及策略选项来自同一服务端产品预设目录，模型服务商目录不承担模板职责

#### Scenario: 目录所有权与注册错误
- **WHEN** 调用方修改获取的模板列表，或开发者登记重复模板及不存在策略的切分方案
- **THEN** 目录实例不受外部修改，错误注册在构造时明确失败

### Requirement: 配置逻辑引用一致性

系统 SHALL 对当前启用 LLM、默认 Embedder 和知识库等真实引用进行同企业用途校验，拒绝删除被引用模型以及原地更改其用途、协议、地址、模型名或维度。创建引用与删除 MUST 通过应用事务协调；替换模型需新建配置并显式切换，知识库切换需重建索引。历史会话 model_id SHALL 仅作为最近生成快照，不参与模型删除保护。

#### Scenario: 修改被引用模型
- **WHEN** 管理员修改当前启用 LLM、默认 Embedder 或知识库仍引用模型的地址或维度
- **THEN** 返回冲突并保留原配置，密钥更新仍可按明确字段语义处理

#### Scenario: 删除仅剩历史快照的旧模型
- **WHEN** 旧模型已不是当前启用 LLM，也无默认 Embedder 或知识库等真实引用，仅有历史会话 model_id 快照
- **THEN** 删除允许，历史消息与来源快照保留，会话下一条消息使用企业当前启用模型
