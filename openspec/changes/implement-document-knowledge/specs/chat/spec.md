# Spec Delta

## Purpose

以聊天为企业首页，提供本用户历史、普通模型对话和使用企业知识库的问答，持久化消息、引用及生成终态。

## ADDED Requirements

### Requirement: 用户所属对话与独立配置

系统 SHALL 按企业及用户隔离会话和消息，支持创建、读取、更新、删除及历史恢复；企业管理员不得自动读取其他用户对话。新会话复制企业模板中的 Prompt、生成及检索参数，当前会话修改仅影响后续回答。会话输入 MUST 不接受 model_id，模型由企业当前启用状态决定。

#### Scenario: 聊天首页与历史恢复
- **WHEN** 企业成员登录后进入首页或打开历史对话地址
- **THEN** 首页提供聊天，历史恢复本用户消息、配置和引用，不显示其他用户或企业的数据

#### Scenario: 尚未启用 LLM
- **WHEN** 用户在尚未启用 LLM 的企业创建对话
- **THEN** 可显示配置引导，发送请求被明确拒绝而不伪造回答

#### Scenario: 生成中跨用户访问
- **WHEN** 其他用户或企业向正在生成的会话发送请求
- **THEN** 返回 404 而非生成冲突，不泄露其存在及生成状态

### Requirement: 每次生成读取企业启用模型

系统 SHALL 在新旧会话每次发送时读取企业当前启用 LLM，并在请求开始时捕获完整模型配置。启用切换 MUST 只影响之后发起的请求，不改变正在流式的生成。chat_sessions.model_id SHALL 仅由服务端记录最近生成模型的只读快照，不决定下一次调用，也不参与旧模型删除保护；聊天页 MUST 不提供模型选择。

#### Scenario: 旧会话继续发送
- **WHEN** 企业从 LLM A 切换启用至 LLM B 后，用户在既有会话继续提问
- **THEN** 下一条消息使用 B，会话中的旧模型快照不使其继续调用 A

#### Scenario: 流式期间切换启用
- **WHEN** 使用 A 的回答正在流式输出，此时管理员切换启用至 B
- **THEN** 本次回答继续使用开始时捕获的 A 完整配置，之后发起的消息使用 B

### Requirement: 简洁的聊天工作区

系统 SHALL 沿用标准侧边文字导航、顶部栏和页面内容区，在内容卡片内提供本用户历史和聊天；空态输入位于卡片中央，有消息后位于卡片底部。用户消息气泡 SHALL 靠右且头像位于右侧，AI 回答 SHALL 靠左且头像位于左侧，正文 MUST 保持左对齐；历史、流式及窄屏使用一致的角色排布。Enter SHALL 发送、Shift+Enter SHALL 换行，IME composing 期间 MUST 不误发送。历史和流式回答 MUST 统一安全渲染 Markdown，支持复制回答及来源 Drawer；自动滚动 SHALL 仅在接近底部时跟随，用户向上阅读时不被新内容拉回。

#### Scenario: 标准应用框架内聊天
- **WHEN** 用户在桌面进入新对话或恢复历史对话
- **THEN** 标准侧边文字导航和顶部栏仍可见，历史和聊天位于页面内容区的卡片内，消息左右排布与模型列表启用行为保持一致

#### Scenario: 从空对话开始
- **WHEN** 用户进入新对话并发送第一条消息
- **THEN** 输入从聊天卡片中央转至卡片底部，卡片内仍可恢复本用户历史，聊天页不出现模型选择

#### Scenario: 键盘和中文输入
- **WHEN** 用户按 Enter、Shift+Enter 或在中文输入法 composing 期间按 Enter
- **THEN** 分别发送、换行或仅完成输入法操作，正在选字时不触发发送

#### Scenario: 用户与 AI 消息左右排布
- **WHEN** 用户发送消息、接收流式回答或刷新恢复历史
- **THEN** 用户气泡位于消息区右侧且头像在气泡右侧，AI 正文位于左侧且头像在正文左侧，正文仍左对齐

#### Scenario: 窄屏和长内容
- **WHEN** 用户在桌面或 390px 窄屏查看多段长文本、长 URL、代码块和表格
- **THEN** 用户文本保留换行并自动折行，AI 代码块和表格在内部横向滚动，角色左右排布不变且消息不撑宽页面

#### Scenario: 查看 Markdown 回答及来源
- **WHEN** 用户查看历史或流式回答并执行复制、打开来源
- **THEN** 历史和流式回答使用相同的安全 Markdown 展示，复制返回回答正文，来源 Drawer 展示本次保存的引用快照

#### Scenario: 阅读历史时接收新内容
- **WHEN** 用户向上滚动阅读历史时流式输出继续到达
- **THEN** 页面保留阅读位置；回到接近底部后才继续跟随新内容

#### Scenario: 同 URL 新建对话
- **WHEN** 新会话创建尚未返回时用户再次点击新建，前后 URL 都为首页
- **THEN** 旧创建、加载和流式请求失效，过期结果不得触发跳转、继续发送或污染新页面，已提交写入仍以服务端记录为准

### Requirement: 普通聊天与知识问答

系统 SHALL 在无知识库选择时进行普通对话，在选择知识库时先校验归属、索引能力并检索，再把命中资料作为证据交给 Chat 模型。无命中 MUST 明确提示且不伪造来源；关键词权重和混合融合分数不得使用纯向量相似度阈值。

#### Scenario: 使用资料回答
- **WHEN** 用户选择知识库并询问资料中的事实
- **THEN** 模型实际接收检索内容，回答携带可查看的资料引用，刷新后仍可恢复

#### Scenario: 所选知识库无命中
- **WHEN** 本次检索没有返回有效资料
- **THEN** 回答明确显示未在所选知识库中找到相关资料，来源为空

### Requirement: 流式生成与明确终态

系统 SHALL 使用真实 OpenAI 兼容或 Ollama 流式协议，先保存用户及助手消息，再推送 SSE 的 message、sources、delta、done 或 error。停止、失败和断流 MUST 保留已有文本与明确状态；连接开启前的拒绝仍返回 JSON 错误。

#### Scenario: 停止部分生成
- **WHEN** 用户在收到部分回答后点击停止
- **THEN** 取消上游生成并保存 cancelled 状态及部分文本，刷新不再显示生成中

#### Scenario: 上游提前断流
- **WHEN** 模型已输出部分内容却未正常结束
- **THEN** 保留部分回答并标记失败，不把截断文本当作完成

### Requirement: 生成并发与恢复

系统 SHALL 在短事务中领取同一会话生成资格，每会话同时最多一个生成，生成期间拒绝会话更新或删除；网络调用不持有数据库长事务。当前单服务启动 MUST 把中断的生成恢复为失败。

#### Scenario: 同时发送
- **WHEN** 同一会话已有生成时再次发送
- **THEN** 第二次返回冲突且不插入重复问答

#### Scenario: 服务重启
- **WHEN** 单服务重启时数据库存在生成中消息
- **THEN** 消息恢复为失败并保留已保存文本，不永久停留生成中

### Requirement: 来源快照与有界上下文

系统 SHALL 保存本次回答的资料内容快照，后续资料编辑、重建和删除不得改写历史引用。输入、来源及历史传入模型前必须受界限控制，仅完整完成的问答轮次进入后续历史；客户端取消等待后应重新查询持久状态。

#### Scenario: 原资料变化
- **WHEN** 资料在回答完成后被修改或删除
- **THEN** 历史回答仍展示当时使用的来源快照，不借新资料内容替换旧引用

#### Scenario: 取消等待后恢复
- **WHEN** 浏览器取消或连接超时后重新进入对话
- **THEN** 以服务端消息和状态恢复页面，不假定取消已回滚
