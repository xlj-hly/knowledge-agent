# Design

## Context

Go/Gin 服务使用 domain、app、infra、transport 四层，PostgreSQL 管理 SaaS 与业务权威记录，S3/filesystem 保存原件；React 使用页面目录、fetch 和 Zustand 登录会话。AnythingLLM 是产品交互与配置体验的主要参考，WeKnora 是 Go 底层实现参考，切分源码复用保留 MIT 声明。继续使用本项目身份和数据归属，不迁入示例项目的完整业务体系。

## Goals / Non-Goals

**Goals:** 从 React 页面完成 LLM、Embedder、向量连接、默认值和 Prompt 配置，导入资料、预览切分、查看分块、重建与检索，并从聊天首页完成普通对话或带来源的知识问答。外部故障、异步任务和生成生命周期有可恢复的持久状态。

**Non-Goals:** 本轮不涉及公有私有、FAQ/Wiki、Agent 框架、新 Workspace 层、uniapp 和本地向量实现。不增加用户未确认的登录、限流、可信代理或注册策略。

## Decisions

### 按能力落实四层

- `domain/ai` 定义 Chat / Embedding 用途、企业启用状态与新建模板；`domain/knowledge` 定义知识库、资料、分块和处理代；`domain/chat` 定义用户会话、消息及来源快照。内层不依赖 Gin、GORM 或具体外部协议。
- `app/ai` 管理模型与企业模板；`app/knowledge` 管理向量连接、原件、解析索引、检索与重建；`app/chat` 通过公开模型和知识检索能力编排生成。每个能力维护 DTO 与实际消费的端口，不直接访问另一能力私有仓储。
- `infra/persistence` 实现仓储；`infra/ai` 实现服务商目录、模型发现与测试、Embedding 和流式 Chat；`infra/knowledge` 实现本地解析、DocReader、切分和各向量引擎适配；原件依赖已有统一对象存储。HTTP 只负责有界输入、身份转交和 JSON/SSE 映射。
- `bootstrap` 统一注入 SaaS 身份、配置引用协调和外部能力；运行入口负责后台任务、生成恢复及退出，构造函数不启动 goroutine。

### 配置是页面管理的企业能力

配置页面使用 Ant Design；跨页导航只由侧栏承担，不额外叠加指向同样菜单的 Tab。服务商以 Logo 卡片展示，点击直接进入对应连接配置；名称、说明、嵌入品牌资源、能力、地址、发现支持及模型候选由后端注册目录统一提供，前端仅负责展示和表单草稿。目录支持搜索。向量配置从引擎目录读取实际已实现模块的定义与字段，不维护前端品牌表单分支。

企业默认值先展示五组当前值摘要，模型与连接组只编辑默认 Embedder 和向量连接，启用 LLM 由模型列表单独管理。编辑时用抽屉呈现单组字段。仅在明确保存后合并本组字段与最新已保存模板再提交，取消放弃本次草稿，失败保留草稿供修正；不同组已保存值不会被旧表单覆盖。Settings 保存输入与响应分离，输入不含 chat_model_id，服务端保留当前启用状态，避免旧草稿覆盖。

`ai_models` 统一存储 Chat 和 Embedding，模型服务商映射到实际 OpenAI 兼容或 Ollama 协议。服务商地址、候选模型、Prompt 和切分方案有明确预设，允许发现远端模型或手填目录外模型。预设不伪造服务可用性；当前表单可直接调用测试，Embedding 检测真实维度。

### Go 显式注册与预设模块

借鉴 WeKnora 的类型化厂商 Definition、逐厂商文件和显式 Builtins 组装；保留本项目端口与配置归属。预设元数据、厂商兼容差异和协议驱动位于 `infra/ai`，应用层定义消费方 Catalog 端口。构建时检查重复 ID、未知驱动与无效能力，bootstrap 创建同一注册实例并注入配置、探测、聊天、Embedding；不使用全局可变注册、`init()` 副作用、反射或 Go 动态插件。

领域模型只校验结构和纯业务规则，不维护品牌到协议的 switch。应用用例经 Catalog 检查已注册服务商及用途；协议执行也从注册目录解析，未知服务商不得静默降级。注册对象构建后只读，输入与公开列表独立复制，避免调用方修改或请求间串扰。

Prompt、切分方案与切分策略元数据位于独立的 `infra/ai/presets` 包，由专用 PresetCatalog 端口提供；模型 Registry 不再承担产品模板目录。bootstrap 分别构造并注入目录，类型化构造校验重复标识、无效模板及方案引用，返回列表独立复制。`GET /api/ai/presets` 提供 prompts、chunking、chunk_strategies；页面统一读取策略名称与选项。策略元数据须与已实现算法一致，添加参数方案不改变执行算法；领域产品默认和业务参数限制继续由内层维护。

新增同协议服务商只需增加定义与资源并在 Builtins 显式登记，不修改聊天、知识库和前端页面；少量参数、地址、发现路径差异由类型化定义或专用驱动封装。新协议必须提供实际驱动，不能用一条配置冒充支持。企业 API Key、地址与模型仍在各自连接中，不把凭据放入静态预设。Anthropic、Bedrock、内置模型运行时及未实现向量引擎不在本轮兼容目录扩展中。

向量使用显式引擎定义和驱动注册。`app/knowledge` 通过 VectorCatalog 校验连接并提供目录，向量写入、查询和删除由统一 Vectors 端口分派，领域和知识库流程不按品牌分支。注册 Qdrant、PGVector、Chroma、Chroma Cloud、Pinecone、Milvus、Zilliz Cloud、Weaviate、AstraDB、Elasticsearch、OpenSearch、Doris、Tencent VectorDB 共 13 个远程引擎模块；同协议复用驱动，专用差异封装在模块中。

每个模块声明连接字段的 key、名称、类型、必填、敏感输入、默认值、说明、选项及引用后不可变属性，页面读取元数据生成表单，不维护品牌字段分支。统一连接 config 以 JSONB 存储字符串值，驱动边界解码为专用类型；未知键、null、错误类型及无效参数明确拒绝。已有授权配置接口返回完整 config，包括凭据，不设置另行过滤的 PublicStore 或 configured_secrets 标记。所有字段按提交完整替换，不合并旧值或继承旧凭据；空串直接生效，必填字段缺失或为空时拒绝。secret 元数据用于输入类型及默认值约束，不过滤响应。被引用连接的不可变字段禁止更改，凭据仍可更新。

各驱动必须实现真实协议、处理维度并按企业、知识库、资料与处理代限定操作；远端需要 UUID 时使用确定性 ID 并保留原始 chunk_id。替换只写当前处理代，清理不能删除新代。连接由每次调用传入，数据库连接明确释放。已有 Qdrant 配置转换为 config 后移除旧列，保留记录、索引和账号，不清空数据、不建立双轨读取。

`ai_settings.chat_model_id` 是企业唯一启用 LLM，企业管理员在模型列表通过无请求体的 `PUT /api/ai/models/:id/activate` 切换，校验同企业及 chat 用途后返回完整 Settings。其余字段作为新建模板：新会话复制 Prompt、生成及检索参数，新知识库复制 Embedder、向量连接、解析和切分参数，此后独立维护。`GET/PUT /ai/settings` 响应含 chat_model_id，保存输入不接受该字段并保留当前启用状态。初始配置不绑定虚假模型；选择向量能力而缺少连接时明确提示。

模型配置输出直接包含 api_key 字符串，移除 has_api_key 标记；输入采用完整表单的 api_key 字符串，保存不继承旧值，空串按服务商字段规则处理。模型发现和测试使用当前表单中的地址、用途与凭据，不接受已存模型 ID 回读密钥。既有企业读写授权保持：企业管理员管理配置，具有读取权限的本企业用户按接口契约读取配置；不扩大跨企业或未授权访问。凭据不写入静态包、浏览器持久化或日志。当前启用 LLM、默认 Embedder、知识库等真实引用保护模型不被删除或原地更换用途、协议、地址、模型名或维度，替换需新建配置并显式切换；历史会话 model_id 只是最近生成快照，不参与引用保护。同企业应用事务协调创建引用和删除，不能只做事务外检查。

平台企业微信配置同样使用原值回填：平台授权 GET/PUT 返回 app_id 与 app_secret，保存完整提交两项有效值，空值拒绝，不继承旧密钥。wechat_config_version 的并发失效复核保留。公共站点、普通微信登录和用户资料不提供 AppSecret、密码散列或微信临时 session_key。

### 索引能力和查询策略独立

知识库 `indexing_mode` 为 `keyword` 或 `hybrid`，决定导入时准备关键词或关键词与向量索引；新库默认后者。`retrieval_mode` 为 `keyword`、`vector` 或 `hybrid`，决定查询已有索引的方式；策略切换不需重建，不支持的组合明确拒绝。关键词是显式高级选择，外部依赖失败不静默降级。

切分支持 auto、recursive、heading，预览与后台使用同一实现且预览不写入。`context_header` 单独保留标题层级，向量化及问答使用标题与正文，原文 Unicode 字符范围保持独立。

### 异步资料处理与安全重建

文件最多 10 MiB，解析正文最多 2 MiB；TXT、Markdown、CSV、JSON、DOCX 本地有界解析，PDF 使用明确配置的 WeKnora DocReader HTTP 服务。原文件只通过鉴权 API 下载。

任务持久化为 queued、processing、completed、failed、deleting，以 attempt 与租约防止旧任务覆盖新代，重启可重新领取。检索必须在 PostgreSQL 核对同企业、同库、同资料的当前完成代；向量存储是可重建索引。

已有资料时，改变索引能力、模型、向量连接、解析或切分配置须显式确认整库重建。重建在事务中更新配置、失效全部旧代并排队，保留原件，人工分块编辑重新生成。存在 processing 或 deleting 资料时拒绝，避免任务交错。后台按新配置逐项处理，未完成资料不参与检索。

文档记录实际 `index_store_id`，旧清理目标持久化 `store_id + attempt`，即使换连接也能从原地址回收。删除和重处理先失效业务可见性，再幂等回收原件、分块、向量；失败保留可重试状态，不用数据库事务伪装跨资源原子提交。

### 聊天生命周期和引用

企业首页 `/` 提供新对话，`/chat/:id` 恢复本用户历史；知识库和配置为独立页面。会话、消息按企业及 user_id 限定，管理员不自动拥有他人对话。创建时可以尚未启用 LLM 并显示引导，发送必须有有效的企业当前启用 Chat 模型。当前对话独立保存知识库、Prompt、生成及检索配置，修改只影响后续回答；聊天页不提供模型选择。

所有新旧会话每次发送都重新解析 `ai_settings.chat_model_id`，请求开始时捕获完整模型配置，切换启用状态不改变正在流式的请求。SessionInput 不接受 model_id；输出仍可包含最近生成模型的只读快照，由服务端在生成时更新，历史快照不决定下一次调用，也不锁定旧模型删除。

发送在短事务领取会话生成资格并保存消息，同一会话只允许一个生成，生成中拒绝修改和删除。必须先按企业和所有者确认会话，其他用户或企业即使访问正在生成的会话也返回 404，不先暴露生成冲突。检索及上游模型在事务外执行，总期限 2 分钟。SSE 推送 message、sources、delta、done 或 error；连接开启前失败保留 JSON 错误语义。停止或客户端取消会终止上游并保留部分输出，失败和截断标记失败；单服务启动把中断的生成恢复为失败。

消息保存本轮来源内容快照，资料后续修改、重建、删除不改写历史引用。无知识命中明确提示，不伪造来源；只有完整完成的问答轮次进入历史。向量阈值不应用于关键词权重和混合融合分数。输入、引用、历史均有明确大小预算，不向模型无限传递资料。

React 聊天沿用标准应用布局的侧边文字导航、顶部栏和内容区，在内容卡片内组织本用户历史和对话。用户消息气泡靠右、头像在右，AI 回答靠左、头像在左。气泡正文保持左对齐，用户文本保留输入换行，长文字和 URL 自动折行；AI 代码块与表格在内部横向滚动，不撑宽消息区。历史、流式及窄屏使用一致的角色排布，通过真实浏览器元素位置验证。

无消息时输入位于聊天卡片中央，出现消息后位于卡片底部。Enter 发送，Shift+Enter 换行，中文输入法 composing 期间不发送。历史和流式回答统一安全渲染 Markdown，回答支持复制，来源在 Drawer 展示；接近底部时跟随流式输出，用户上滚阅读时保持阅读位置。此次不扩展上传、Agent、消息编辑或重新生成。

React 普通请求使用 15 秒总期限，对话流使用 150 秒无数据期限并支持停止及卸载取消。草稿和流式状态归页面，权威历史由服务端保存；身份变化、新建或重置都失效旧创建、加载和流式请求，新建前后 URL 相同也必须处理。过期创建不得跳转或继续发送，响应不确定时重新读取持久状态。

## Risks / Trade-offs

- 预设和协议适配不能保证实际服务可用或效果达标：提供表单测试，分别验证受控模型协议、真实 Qdrant、实际模型和 DocReader。
- 多资源部分成功：持久化任务、旧连接快照及幂等清理承担恢复责任，检索只接受当前完成代。
- Prompt、生成、检索和知识处理模板与既有对象分离；启用 LLM 则明确影响所有会话下一条消息，流式请求固定开始时模型，避免切换期间混用配置。
- 当前单服务生成恢复不代表多副本分布式任务接管；当前实现和部署按单服务生命周期验证。

## Migration Plan

`db/saas.sql` 保持唯一完整结构文件，共十二张表，仅用于空库初始化。现有开发库先核对结构，显式执行匹配当前目标的 DDL；保留已有 SaaS 账号、知识数据和模型 ID，统一模型归属至 `ai_models` 并同步引用，增加模板、聊天、标题和清理归属字段。不保留旧模型 API 或开发期双轨逻辑，不因重构自动清空数据或创建备份。

执行快速检查、真实 PostgreSQL 集成、Qdrant 生命周期及浏览器流程后更新本地 server/web，并保持服务运行。验证记录明确已执行、跳过和外部替代边界，不能把受控模型上游当作实际模型效果验收。
