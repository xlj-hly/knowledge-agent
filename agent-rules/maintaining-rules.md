# 规范维护

适用：新增、修改或整理开发规范、规则索引及加载入口。

### DOC-001：从真实问题沉淀规则

- 依据实际改动、缺陷、评审纠正或已确认的项目约定，提炼可复用要求。写清触发条件、执行动作和可检查的结果。
- 一次性实现细节留在代码或变更说明中；不能凭单次修复新增全局架构、工具选型或开发流程要求。
- 在变更说明中记录更新所依据的问题及适用范围；规则正文保留执行要求，不记录学习过程或任务流水账。

### DOC-002：优先修订，避免重复

- 更新前检索已有规则及引用，已有要求不清楚时澄清原文，已有场景缺步骤时补充原场景。
- 共同要求只在一处定义，其他文档通过链接及规则 ID 引用；消除重复或冲突，不追加相近条目绕过原规则。

### DOC-003：放在实际适用范围

- 所有模块共同遵守的要求放根 `AGENTS.md`；模块约定放对应模块 `AGENTS.md`；仅特定任务触发的要求放任务规范，并在 `meta.yaml` 声明触发条件。
- 只有存在独立触发条件和不能归入现有规范的要求时才新建文档；根入口只保留通用原则和加载指引，具体任务步骤放对应文档。

### DOC-004：同步入口并检查引用

- 新增、移动、合并或删除规范时，同步受影响的 `AGENTS.md` 加载指引、`meta.yaml` 和 `agent-rules/README.md`，检查跨文档链接与引用。
- 保持现有规则 ID 稳定，新 ID 不得重复；删除或合并后同步引用，不把旧 ID 分配给无关要求。
- 完成后核对加载条件能覆盖目标路径或任务，索引和链接指向现存文件，规则之间没有矛盾。

### DOC-005：维护也包括删减

- 项目结构、接口或工具变化导致要求失效时，同步修正或删除，不让过时步骤继续约束后续任务。
- 删除无独立价值的重复项，合并触发条件与要求重叠的文档。保留仍有适用场景的低频要求，不以近期未触发作为失效依据。
