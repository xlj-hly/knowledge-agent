# 测试规范

适用：新增或修改业务行为、修复缺陷、编写测试及其辅助代码、选择回归范围。

### TEST-001：先确定验收目标

- 从需求确定前置条件、操作、可观察结果和关键风险，再选择测试；不能仅从已有函数或接口列表反推用例。
- 每个用例应能说明哪一种业务错误会使其失败。文档、纯格式等低影响修改不机械新增测试。

### TEST-002：按验证目标选择层级

| 层级 | 验证内容 | 执行边界 |
| --- | --- | --- |
| 单元 / 组件 | 计算、校验、状态转换和局部交互 | 真实被测单元或组件，依赖可按目标替换 |
| 接口 / 集成 | 请求处理、权限、序列化和模块协作 | 实际处理链路及本次需要验证的存储或适配实现 |
| 业务流程 | 跨操作、跨模块的业务闭环 | 同一业务对象贯穿必要步骤，检查最终状态 |
| 产品 E2E | 用户从实际入口完成业务目标 | 真实界面或平台入口，贯通该流程实际涉及的后端与持久化路径 |

- 采用足以发现目标缺陷的执行层；局部业务分支用快速测试，保留关键跨边界验证。
- 接口流程、浏览器、模拟器和真实外部服务分别说明覆盖范围；文件命名不作为覆盖依据。

### TEST-003：覆盖关键业务流程与用户入口

- 新增或改变关键业务流程时，必须新增、更新或复用对应流程用例；复用时明确其覆盖的验收目标。
- 每条流程围绕一个用户目标，串联真实关联步骤并传递实际生成的数据，不依赖其他测试先执行。
- 涉及界面操作、登录态、导航、前后端衔接或平台能力的关键用户路径，必须保留真实用户入口到业务结果的 E2E 覆盖。
- 仅后端内部局部变化且未改变用户入口或前后端契约时，使用受影响的接口 / 流程集成验证，复用已有 E2E 覆盖，不强制新增界面 E2E。
- React 验证受影响浏览器入口；uni-app 验证实际使用且受影响的平台，平台专属行为在对应端验证。

### TEST-004：断言业务结果和状态变化

- 断言具体结果、状态转换与副作用；接口可达、HTTP 200、退出码为零或响应非空只能作为中间检查。
- 写入后通过后续读取确认生效；更新、删除按业务语义确认新状态，并检查相关数据或其他身份未被误伤。
- 预期值来自需求和受控数据，不调用同一被测逻辑生成预期。问答、检索等场景使用可区分事实，避免在问题中泄露预期答案。
- 核心验收条件必须使用失败即使测试失败的断言；辅助质量观察单独记录，不能替代核心断言。

### TEST-005：替身不能替掉被验收的行为

- mock、fake 或本地服务用于隔离本次验证范围外的依赖；保留被验收的业务编排、状态变化及必要的序列化和存储行为。
- 外部服务替身遵循实际接口契约，覆盖本次涉及的成功与失败语义；外部适配或协议变更时，按风险补充真实集成验证，并报告未验证的真实接入能力。
- 流程测试不得把每一步都替换为预设成功结果；全部拦截业务 API 的界面测试用于验证页面，不能计为前后端贯通的产品 E2E。
- 优先断言可观察结果；仅当调用本身是契约时检查调用次数或参数，不把测试固定在私有实现顺序上。

### TEST-006：验证关键失败和副作用约束

- 根据风险补充非法输入、权限不足、依赖失败、重复提交、取消或超时等相关分支。
- 失败与未授权操作检查不应发生的写入、资源创建或其他副作用；部分成功检查实际完成和未完成的范围。
- 重试或重复操作检查业务约定的最终状态，不能仅检查按钮禁用或调用次数。

### TEST-007：异步过程按条件等待

- 异步任务等待明确状态或可观察条件，设置超时，失败时保留步骤和最后状态；不能只检查任务已受理。
- 轮询、重试、节流等局部逻辑使用可控时间，保留被测逻辑；真实进程中断或超时边界使用相应执行方式验证。
- 避免固定长时间 sleep 和无条件重试整个失败用例；先定位竞态、状态泄漏或环境依赖，不用增加超时掩盖问题。

### TEST-008：隔离数据与清理资源

- 使用测试自有身份、目录、数据库或命名空间，不覆盖用户数据；只读用例可复用不可变 fixture，可变状态按用例隔离。
- 显式控制影响结果的配置、语言、时区、代理和环境变量，恢复进程状态，清理连接、监听器、计时器及临时资源。
- 真实外部服务测试单独显式启用，使用指定测试环境和可回收数据，不因本机存在凭据而自动联网或执行生产写操作。
- 在断言可能失败前记录已创建资源，并在结束路径清理；清理失败保留资源标识和原因，使对应测试失败。

### TEST-009：保留回归价值并控制成本

- 缺陷修复优先添加能复现目标问题的回归用例，确认失败来自目标缺陷，修复后验证通过；无法自动复现时记录可重复步骤和未覆盖范围。
- 复用已有测试能力与共享辅助代码，回归范围覆盖受影响调用方和流程；不为每个分支重复启动完整系统。
- 重构测试时保留原有行为覆盖；不通过削弱断言、扩大跳过或 mock 掉核心路径获得通过或提速。
- 昂贵测试按风险执行，扩展或优化时核对代表性耗时；不以固定测试数量、覆盖率或机器相关耗时阈值替代验收。

### TEST-010：交付真实执行证据

- 执行前核对项目测试入口，使用实际命令；报告覆盖的业务目标、执行层、目标平台及关键替身边界。
- 区分通过、失败、跳过、未执行和环境阻塞；缺少凭据、测试全被跳过或只有空套件不能算目标流程通过。
- 核心流程未执行时明确列为未验证，不能用其他套件或构建成功替代；保留失败步骤、实际结果和必要的脱敏证据。
